## 清洗上游响应 id 里的节点内网地址（21:49 提交，21:50 部署）

**问题**：上游 PD 分离推理通道把节点的内网地址编进了响应 `id`
（`chatcmpl-___prefill_addr_<ip>:<port>___decode_addr_<ip>:<port>_<32hex>`），
流式响应的**每个分块**都带。于是每个调用方——以及它背后的日志与 APM——都拿得到
上游的私网拓扑。实测 `deepseek/deepseek-v4-flash`（10.119.x:7100/7101）与
`z-ai/glm-5.3-flash`（10.234.x:8998）都漏，`/v1/chat/completions` 与 `/v1/messages`
都漏；claude/qwen 系干净（`gen-…` / 裸 hex）。所以判定条件只能是**形状**，不能按模型枚举。

**落点**：`relay/common/response_model.go` 那条 `responseModelWriter` 就是为响应改写而生的，
它已经按 Content-Type 分好 `sse` / `json` / `passthrough`，并且处理了跨分块切帧——
正是需要的，不用另起一层。

- 新增 `relay/common/response_id.go`：`ScrubUpstreamIds(data []byte) []byte`，
  用 gjson/sjson 只改 `id` 字段。**不 scrub 正文**——模型回答里出现 IP 是合法内容
  （用户问网络问题就会）。正则对不上但 id 里还留着地址标记时给 `redacted` 兜底。
- `relay/common/response_model.go`：`WrapResponseModelWriter` 里加一路 `rewritePayload`
  （先清洗、再改写模型名）。
  🔴 **清洗绝不能挂在 `response_model_name` 渠道开关下**：那个开关只管模型名改写，
  关掉它的渠道一样会漏。原实现是 `if !setting.ResponseModelName { return no-op }`，
  现在 writer 一律装上、只有 `rewriter` 是可选的（nil 即关闭）。
- `relay/channel/openai/relay_realtime.go`：realtime 不写 `c.Writer`（websocket 自己转发），
  在它自己那处 `responseModel.Rewrite` 旁边另外调一次。
- 上游文件的两处改动都带 `// ===== CUSTOM START/END =====`（CLAUDE.md Rule 8）。

**已知未覆盖**：`passthrough` 分支（非 2xx，或上游响应带 `Content-Encoding`）不改写。

### 🔴 Go 的 RE2 不会在字符类里展开 `\d`

第一版正则写成 `[\d.]+`，结果**永远匹配不上**，每个 id 都落到 `redacted` 兜底分支。
Go 的 `regexp` 只把 `\d` 当 Perl 类在**字符类之外**用；字符类里 `[\d.]` 被当成字面量
`\`、`d`、`.` 三个字符（PCRE 不是这样）。改成 `[0-9.]` 即好。
**症状有欺骗性**：不报错、不 panic，只是"清洗后变成 redacted"，看起来像正则写窄了。
