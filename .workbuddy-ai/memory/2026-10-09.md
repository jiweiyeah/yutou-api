# 2026-10-09

## 排查：生产 `/api/channel/multi_key/manage` 大量 403

**结论：不是权限问题，是「安全验证（step-up）过期」，属设计行为。**

- 复现（root token + 无会话 cookie，`action=get_key`）：
  `HTTP 403 {"code":"VERIFICATION_REQUIRED","message":"需要安全验证","success":false}`
- 该路由 `router/channel-router.go:74` 权限 = `authz.ChannelOperate`（admin 基线**有**），
  所以 403 不可能来自 `RequirePermission`；handler 内 `controller/channel.go:2011 requireActiveSecureVerification`
  是唯一能吐 403 的地方（另两处 `ApiErrorI18n` 走的是 HTTP **200**，别被误导）。
- 只有 `action=get_key`（查看/复制单条密钥）走这道校验；`SecureVerificationTimeout = 300s`（middleware/secure_verification.go:16）。
- 实例：user 247 `linuxdo_246`（admin role=10，`auth_method=access_token`），
  21:12:15–21:16:26 连刷 **90 条** 403；上一次成功 get_key 21:12:08，
  最后一次 `/api/verify` 21:07:12 → +300s = 21:12:12，首个 403 在 21:12:15 ⇒ **VERIFICATION_EXPIRED**。
  21:16:50 重新 `/api/verify` 后立刻恢复成功。
- 该用户有 user 级覆盖 `user:247 → channel.secret_view/sensitive_write = allow`（casbin_rule 里
  subject 格式是 `user:<id>` / `role:<key>`，**不是** `u:<id>`）。

## 顺手记下的排查技巧

- ⚠️ `docker logs --since/--until` 在 yutou-prod 上**恒返回 0 行**（json.log 569MB，docker 解析不了/已轮转）。
  要查历史请求必须直接 grep 原始 json 日志：
  `/var/lib/docker/containers/<CID>/<CID>-json.log`，按 envelope 里的 UTC 时间戳
  `2026-10-09T13:1x:` 过滤（本地 21:1x = UTC 13:1x），再筛 `[GIN]` 行取状态码。
- `logs.other` 里 `op.action = "generic"` + `audit_info.status=403` ⇒ 请求**在 handler 埋点之前就中止了**
  （兜底审计 `finishAdminAudit` 记的），据此可判断失败发生在鉴权/校验阶段而非业务分支。
- 403 风暴会在 `logs`(type=3) 里留下大量噪音行，且**不记录失败原因**（只有状态码）——
  这就是操作日志里看着很吓人但点进去啥也看不到的原因。
