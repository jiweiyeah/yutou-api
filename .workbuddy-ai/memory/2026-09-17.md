### 500 的真因链

`/v1/messages` + `z-ai/glm-5.3-flash`，token `code-api-key`（user `ya-b4trkk7ji8u8iasd`，group `y-api-paid`）：

```
status_code=500, inference request failed: failed to invoke model 'z-ai/glm-5.3-flash'
  from Openrouter: request failed with status 400:
  {..."message":"Image count 11 exceeds limit 8 per request."..."provider_name":"Cloudflare"...}
```

→ **Cline 网关把上游 provider（Cloudflare）的 400 包成了 HTTP 500**。外层 500 是壳。
`other.error_code = bad_response_status_code`（壳的状态码），不含真因。

### 同 request_id 的重试链（关键证据）

- `request_id=…YJNdcooH`：`use_channel=["10852","10844"]` → 10852 500 → 重试 → 10844 400
- `request_id=…tLKnjnAU`：同上

10844（**braintrust**, type 58）给出更直白的上游限制：

```
400 Request exceeds TCP payload budget — payload is 334.3 MiB — 78.3 MiB over the
256.0 MiB budget. Images account for 99% of the payload.
images: 每张 data:image/png;base64 ≈ 30.0 MiB (embed_bytes 31457480), 2880 tokens/张
```

→ 客户端单请求塞了 **11 张 base64 PNG（≈30 MiB/张，合计 334 MiB）**，同时撞上
Cloudflare 的 8 图/请求上限 + Braintrust 的 256 MiB payload 预算。

### 衍生结论

- 500 ∈ `AutomaticRetryStatusCodes`（`100-199,300-399,401-407,409-412,414-503,505-523,525-599`）
  → 这类客户端 payload 错误会被重试，**白传一遍 334 MiB**。而 400 不在列表（从 401 起）→ 只打一次。
- 500 **不触发自动禁用**（默认只认 401）→ 症状会静默持续。
- `"TCP payload budget"` 在本地代码里 grep 不到 → 是上游网关自己的限制，别去仓库里找。

## 工具坑（新发现，已写进 skill）

- **`logs.created_at` 是 bigint（Unix 秒），不是 timestamp**。
  `to_char(created_at,'MM-DD HH24:MI:SS')` → `ERROR: multiple decimal points`。
  必须 `to_char(to_timestamp(created_at) at time zone 'Asia/Shanghai', …)`；
  时间窗过滤直接比数字 `created_at > extract(epoch from now())::bigint - 86400`。
- **`logs` 表没有 `status_code` 列** → 从 `other` 里 regexp 提取或看 `content` 前缀。
- 嵌套 ssh 双引号传 SQL 容易踩坑，改用 `ssh yutou-prod 'docker exec -i … psql -t -A' <<'SQL'` heredoc。
